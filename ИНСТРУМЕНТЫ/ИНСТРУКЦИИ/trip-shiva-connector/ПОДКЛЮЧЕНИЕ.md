# Подключение коннектора за пять минут

Короткая памятка для команды проекта. Подробности — в [ИНСТРУКЦИИ](ИНСТРУКЦИЯ.md).

Коннектор — **программа командной строки**. У него нет сервера, адреса и
«ручек»: он запускается, доводит реестры проекта до трекера и завершается.
Заголовки вроде `x-api-key` задавать негде и не нужно.

---

## 1. Получить токен

Служебный токен SHIVA выдаёт администратор трекера. Личный токен не подходит:
все действия коннектора подписываются им, и по нему видно, где машина, а где
человек.

```powershell
$env:SHIVA_TOKEN = "..."        # PowerShell
```

```bash
export SHIVA_TOKEN=...          # Git Bash, Linux, macOS
```

Переменная живёт до закрытия окна. В репозиторий токен не кладётся никогда.

## 2. Проверить, что токен принят

```bash
curl -H "Authorization: Bearer $SHIVA_TOKEN" https://shiva.imbalanced.tech/shiva/api/v0/session/health-check
```

Ответ `true` — токен работает. `401` — не принят: проверьте, что скопировали
его целиком и что заголовок называется `Authorization`, а не как-то иначе.

## 3. Завести файл проекта

`проекты/<имя>.json` рядом с коннектором:

```json
{
  "имя": "Мой проект",
  "корень": "C:/Проекты/<папка репозитория>",
  "проект": 126,
  "схема": 186,
  "журнал_точек": "docs/ПАКЕТ_АНАЛИТИКИ/ЖУРНАЛ_КОНТРОЛЬНЫХ_ТОЧЕК.md",
  "реестр_требований": "docs/ПАКЕТ_АНАЛИТИКИ/РЕЕСТР_ТРЕБОВАНИЙ.md"
}
```

`проект` и `схема` — номера из трекера; их скажет тот, кто завёл проект в SHIVA.
Пути к реестрам — от корня репозитория. Остальные ключи не нужны, пока не
понадобятся: дефекты, встречи, портфель добавляются позже.

## 4. Проверить связь

```bash
python -m trip_shiva.cli --конфиг проекты/<имя>.json процесс
```

Первая строка ответа — `Проект: … , схема …`. Значит, связь есть.

Дальше коннектор покажет, чего не хватает схеме трекера. Если в плане только
три строки `уникальность` — всё готово. Если больше, схему приводят к модели
один раз на проект:

```bash
python -m trip_shiva.cli --конфиг проекты/<имя>.json процесс --применить
```

## 5. Посмотреть и применить

```bash
python -m trip_shiva.cli --конфиг проекты/<имя>.json план
```

Ничего не пишет — только показывает, что собирается сделать. Устраивает:

```bash
python -m trip_shiva.cli --конфиг проекты/<имя>.json план --применить
```

Всё. Дальше правки вносятся **в реестр**, а коннектор доводит их до трекера.
Обратный порядок — правку в трекере руками — он не откатывает, но покажет
расхождением.

## Если ругается

| Что говорит | Что делать |
|---|---|
| `не задан токен` | шаг 1: переменная `SHIVA_TOKEN` пуста |
| `Настройка не сходится с репозиторием` | назван файл, которого нет: завести его или убрать ключ из конфига |
| `статус «…» не имеет соответствия` | в реестре свои слова вместо канонических статусов — см. §3а инструкции |
| `статус «…» не разобран` | в реестре осталась строка-образец из шаблона |
| `403` | токен отозван или выдан без нужных прав |
| Ответ похож на HTML | неверный адрес трекера в `SHIVA_ENDPOINT`; уберите переменную, адрес по умолчанию верный |

## Чего делать не нужно

- Поднимать сервер, открывать порт, настраивать вебхук — коннектору это не нужно.
- Ставить хук каждому в команде: токен окажется у всех. Один запуск в конвейере
  на ветке интеграции — правильнее.
- Заводить задачи в трекере руками и ждать, что коннектор их подхватит: он
  идёт от реестра к трекеру, а не наоборот.
