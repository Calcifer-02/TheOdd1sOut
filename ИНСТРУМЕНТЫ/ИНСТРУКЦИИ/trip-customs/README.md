# TRIP Customs — File Level Tooling

Локальный инструментарий контроля файлового уровня: он фиксирует фактическую
дельту файлов, применяет активную политику разрешений и выпускает
детерминированные архитектурные находки до фиксации изменения.

## Текущее состояние

На 2026-07-31 staged-first вертикаль реализована и проходит `30` unit-тестов,
`1` real-Git integration test и repository harness. Продуктовый MVP **ещё не
принят и не завершён**: остаются архитектурный engine, security/evidence-срезы
и человеческие gates `DELTA-001` (`docs/sdd/deltas/DELTA-001-mvp.md` — в исходном репозитории средства). Следующая
итерация File Audit Monitor запущена как спецификация
`DELTA-002` (`docs/sdd/deltas/DELTA-002-file-audit-monitor.md` — в исходном репозитории средства), без заявления о
готовой реализации.

## Быстрый вход

1. Прочитать `правила проекта` (`AGENTS.md` — в исходном репозитории средства) и `память` (`MEMORY.md` — в исходном репозитории средства).
2. Проверить `trip policy`, `trip work show` и текущую ветку.
3. Прочитать `порядок потребления архитектуры` (`architecture/CONSUMPTION.md` — в исходном репозитории средства) и
   машинный канон `architecture/architecture.json`.
4. Открыть `SDD-процесс` (`docs/sdd/README.md` — в исходном репозитории средства), активную дельту и рабочий пакет.
5. Запустить проверочную обвязку:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/harness/Invoke-Harness.ps1
```

Для использования готовой staged-вертикали откройте
`пользовательскую инструкцию` (`client/USER_GUIDE.md` — в исходном репозитории средства).
