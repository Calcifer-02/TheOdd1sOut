# TRIPWIRE

TRIPWIRE (каталог `tripwire`, CLI `trip wire`) — TRIP-нативная обвязка
безопасности. Отдельный инструмент семейства слоя B,
который проводит находку по **лестнице вердиктов** и выпускает неизменяемое
свидетельство, а не решение. Инвариант: вердикт выносится детерминированно на
хосте, LLM только советует; конверт питает Gate 6 (безопасность) и класс долга
К13, но вердикт Gate принимает человек.

Проект синтезирован из двух внешних корпусов-обвязок методом адаптации TRIP
(п. 16A.8): дисциплина анти-ложных-срабатываний Visa и доказательное ядро ptai —
переложены на рельсы существующей экосистемы, без форка и без двойников
инструментов.

## Лестница вердиктов

| Ступень | Что делает | Источник идеи | Статус |
|---|---|---|---|
| `candidate` | taint-генератор SEC-001 (внешний ввод -> опасный sink), избыточный | Visa (find), КАСТА (правила) | **сделано (срез)** |
| `verified-static` | S6-верификатор «предположи, что ложно» -> детерминированный вердикт | Visa S6 | **сделано (срез)** |
| `proven` | артефактный оракул N/N + «контроль, что обязан провалиться» + капсула | ptai (перенос receipt/oracle/capsule) | **сделано, за жёстким gate** |
| `defect` | подтверждённая находка -> дефект с анализом влияния | trip-bug-loop | следующий срез |
| `gate` | вердикт Gate 6 (безопасность); принято -> долг К13 | реестр контрольных точек TRIP | процедура TRIP |

Первый срез — **оборонительный**: статика и верификация без живой эксплуатации.

## Что этот инструмент делает сам, а что переиспользует

**Владеет:** правила `SEC-*`, верификатор, контракт конверта `trip.sec-finding/v1`,
оркестратор лестницы, позже — ступень `proven`.

**Переиспользует по контрактам (без двойников):** привязку находок к требованию и
классу важности — TRIP Trace Service (его граф — трассируемость, не вызовы;
межпроцедурный taint — отдельная забота, перенос движка Visa, R-014);
структурные правила формы места — trip-cast;
безопасное живое зондирование и SBOM — TRIP Inspectors; хранилище доказательств
и гейты — trip-cli; петля дефекта — trip-bug-loop; модель угроз агента —
trip-browser-tester; закалка LLM — TRIP Reviewer. Интеграция — через контракт-файл
в репозитории потребителя, не через RPC.

## Запуск

```bash
# тесты (только stdlib, офлайн, детерминированно)
python -m unittest discover -s tests -t .

# сканирование -> конверт trip.sec-finding/v1 в stdout
PYTHONPATH=src python -m tripwire scan targets/vuln_cmdi.py --basis AR-1

# коды выхода (пригодны для CI-гейта):
#   0 — чисто (нет TRUE_POSITIVE)
#   2 — есть TRUE_POSITIVE
#   3 — partial / needs_review (есть INCONCLUSIVE)
#   1 — техническая ошибка
```

```bash
# привязка находок к требованию и классу важности через TRIP Trace Service
PYTHONPATH=src python -m tripwire scan targets/vuln_cmdi.py --basis R-042 --basis-type R-id \
  --trace targets/trace-view.example.json

# ступень proven: динамическое доказательство за жёстким gate (только echo + временный файл)
PYTHONPATH=src python examples/demo_proven.py
```

Примеры выпущенных артефактов: `out.example.sec-finding.json` (конверт),
`out.example.capsule.json` (портируемая капсула доказательства).

## Поставка выпуском (source-less)

Командам средство отдаётся СОБРАННЫМ файлом, а не исходниками — как остальные
инструменты TRIP/tooling. На метке выпуска CI собирает один переносимый
bytecode-бандл `tripwire-any.tar.gz` (внутри только `.pyc`), публикует его в реестр
generic-пакетов репозитория; потребитель тянет закреплённую версию токеном
развёртывания с правом `read_package_registry`, сверяет SHA-256 и запускает
`./tripwire/trip-wire scan …`. ОС любая (байткод ядра OS-независим), нужен Python
3.11–3.13; многоязычие — opt-in pip-extra. Порядок для потребителя —
`docs/РАЗВЁРТЫВАНИЕ.md` (`docs/РАЗВЁРТЫВАНИЕ.md` — в исходном репозитории средства); конвейер — `.gitlab-ci.yml`.

```bash
# собрать бандл локально (под текущий Python; CI матрицей соберёт 3.11/3.12/3.13)
python tools/release/build_release.py --out release --stage dist/stage
```

## Контролируемые цели (для фальсифицируемости)

- `targets/vuln_cmdi.py` — внешний ввод в `os.system` -> ожидается `TRUE_POSITIVE`;
- `targets/clean_cmdi.py` — тот же код, но санировано `shlex.quote` / внутренняя
  константа -> ожидается `FALSE_POSITIVE` («контроль, который обязан провалиться»);
- `targets/ambiguous_cmdi.py` — параметр не-обработчика -> `INCONCLUSIVE` (needs_review).

## Ограничения среза

Межпроцедурно в пределах модуля (кросс-модульный и многоязычный taint —
R-015); один язык (Python); dotted-имена как записаны; вердикт
детерминирован на хосте, LLM необязателен и вердикт не меняет; ступень `proven`
требует авторизованной живой цели. Дорожная карта — открытые требования в
`docs/РЕЕСТР_ТРЕБОВАНИЙ.md` (R-013, R-015).

## Лицензионный след источников

Visa harness — Apache-2.0 (референс-архитектура + отдельные блоки); ptai — MIT
(перенос капсульного ядра для ступени `proven`, коммерческие «звонки домой» и
установщик без контрольных сумм при переносе вырезаются). Код этого среза —
оригинальный, stdlib, без копирования исходников.
