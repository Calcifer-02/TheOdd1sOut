# Развёртывание TRIP Bug Loop из бандла выпуска

> Файл едет внутри `trip-bug-loop-bundle.tar.gz` из реестра пакетов
> репозитория. Бандл самодостаточен: исходники службы и доступ к серверу
> исходников для развёртывания не нужны.

## Состав бандла

| Что | Зачем |
|---|---|
| `app/` | опубликованное приложение (framework-dependent, нужен ASP.NET Core Runtime 10 либо docker) |
| `Dockerfile.release` | сборка образа из готового `app/`, без исходников |
| `compose.release.yaml` | подъём службы одной командой |
| `trip-bug-loop.example.json` | пример конфигурации проекта |
| `ВЫПУСК.json` | версия, состав и происхождение бандла |

## Подъём службы

```bash
tar -xzf trip-bug-loop-bundle.tar.gz -C trip-bug-loop && cd trip-bug-loop
TRIP_PROJECT_PATH=<каталог проекта> docker compose -f compose.release.yaml up --build -d
```

Служба слушает `http://127.0.0.1:7788`. Конфигурация проекта кладётся в
`<каталог проекта>/.trip/bug-loop.json` по образцу `trip-bug-loop.example.json`.

Без docker служба запускается напрямую (нужен ASP.NET Core Runtime 10 и `git`):

```bash
dotnet app/trip-bug-loop.dll --config <каталог проекта>/.trip/bug-loop.json
```

## Откуда берётся бандл

Реестр пакетов репозитория `TRIP/tooling/trip-bug-loop`, generic-пакет
`trip-bug-loop`, закреплённая версия из замка средств проекта. Доступ на
чтение даёт токен развёртывания с единственным правом
`read_package_registry`; рядом с бандлом лежит отпечаток SHA-256.
