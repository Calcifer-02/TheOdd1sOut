## Назначение и область действия

Надстройка стека закрывает один шаг между «правило существует» и «правило
проверяется здесь»: какой командой оно ловится на стандартном стеке и где
запускается. Идентификаторы берутся из каталога правил проекта; своих
идентификаторов надстройка не заводит. Правило без команды считается
незапускаемым, а не выполненным. Таблица — заготовка для копии в проект:
команды в ней прогнаны в репозитории trip-lint и на пилотных корпусах, а не
вписаны по памяти.

## Стековые грабли

```text
- ESLint не найден → движок notRun и код 1 → поставить eslint в devDependencies фронтенда,
  а не глобально: один экземпляр для редактора и конвейера
- prettier ругается на trip/lint-baseline.json → добавить trip/ и .trip/ в .prettierignore фронтенда
- маркер @req в строчном комментарии → сканер трассы его не читает → перенести в /** … */ или ///
- \b в правилах не видит кириллицу → границы слов только просмотром (?<![\p{L}\p{N}_])
- .editorconfig требует crlf, а .gitattributes держит lf → каждый файл .cs — находка REPO-001 → согласовать канон (Q-004)
- EnforceCodeStyleInBuild выводит правила IDE00xx из проектного .editorconfig на сборку → предупреждения по собственным правилам корпуса
- пакет NuGet той же версии пересобран → кэш ~/.nuget/packages отдаёт старый → tools/pack-nuget.mjs чистит запись кэша
- один ErrorLog на решение перезаписывается каждым проектом → SARIF на проект через assets/dotnet/trip-lint.targets
- корпоративный .editorconfig как есть → правила s_ недостижимы, crlf и BOM → брать редакцию trip-lint из trip-lint init
- имя теста с подчёркиваниями → CA1707 → выключен в пакете, форма Given_When_Then — соглашение
- squawk с неверным именем правила в .squawk.toml молчит без JSON → движок сообщает «отчёт не читается»; имена правил сверять по squawk --help
- squawk считает строки с нуля → движок прибавляет единицу
```
