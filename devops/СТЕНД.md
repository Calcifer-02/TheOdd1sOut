## Назначение и область действия

Документ описывает единственный публичный адрес решения: что где стоит, по
каким путям доступно, как туда попадает код и чем проверяется, что стенд жив.
Локальный запуск описан отдельно — в [порядке запуска](ЗАПУСК.md).

## Адрес и состав

| Что | Публичный путь | Внутри сервера |
|---|---|---|
| Мини-приложение | `https://triadmind.ru/` | `127.0.0.1:15173` (служба `miniapp`) |
| Расчётная часть | `https://triadmind.ru/api/` | `127.0.0.1:18080` (служба `api`) |
| Договор API | `https://triadmind.ru/api/v1/openapi.yaml` | та же служба |
| Страница просмотра договора | `https://triadmind.ru/api/swagger/` | та же служба |
| Приём обновлений чат-ботом | `https://triadmind.ru/bot/` | `127.0.0.1:18081` (служба `bot`) |

Узел: `89.223.45.218`, nginx на стороне сервера, сертификат Let's Encrypt,
выпущенный на одно имя `triadmind.ru`. Поддомены сертификатом не покрыты —
это одна из причин, по которой расчётная часть стоит путём, а не на
`api.triadmind.ru` (см. [ADR-0004](../docs/architecture/ЗАПИСЬ_АРХИТЕКТУРНОГО_РЕШЕНИЯ_ADR-0004.md)).

База данных наружу не выходит: в `compose.yaml` все порты привязаны к петлевому
адресу, и снаружи службы доступны только через внешний узел.

## Конфигурация внешнего узла

Целевое состояние лежит в репозитории: [`devops/nginx/triadmind.ru.conf`](nginx/triadmind.ru.conf).

```sh
sudo cp devops/nginx/triadmind.ru.conf /etc/nginx/sites-available/triadmind.ru
sudo nginx -t && sudo systemctl reload nginx
```

Разбор конфигурации проверен 22.09.2026 на nginx 1.24 — той версии, что стоит
на стенде: `docker run --rm -v <конфигурация>:/etc/nginx/conf.d/triadmind.conf
-v <каталог сертификата>:/etc/letsencrypt nginx:1.24-alpine nginx -t` отвечает
`syntax is ok`. Версия важна: отдельная директива `http2 on` появилась только
в nginx 1.25.1 и здесь не разбирается, поэтому протокол включён формой
`listen 443 ssl http2`.

Два места, которые нужно сверить с действующей конфигурацией до применения,
потому что проверить их снаружи нельзя:

1. **Как отдаётся мини-приложение.** Конфигурация предполагает, что внешний
   узел проксирует его в контейнер на `127.0.0.1:15173`. Если статика
   выложена на сервере файлами, замените этот блок на `root` и `try_files`,
   иначе выкладка сломается.
2. **Пути сертификата.** Указаны обычные для certbot
   (`/etc/letsencrypt/live/triadmind.ru/`).

## Порядок выкладки

Порядок предполагается такой; он записан со слов конфигурации, а не выполнен
автором документа — владелец стенда сверяет его со своим и правит этот раздел.

```sh
git pull                      # взять слитую версию main
docker compose up --build -d  # пересобрать и поднять службы
sh tests/devops/проверка-стенда.sh
```

Выкладка не автоматизирована: конвейер `.github/workflows/ci.yml` собирает и
проверяет, но на сервер ничего не отправляет.

## Проверка

```sh
sh tests/devops/проверка-стенда.sh
```

Проверка берёт адрес из [`DATA-API.yaml`](../DATA-API.yaml), а не хранит свой,
и сверяет: сертификат принимается без послаблений; мини-приложение отдаётся по
корню; расчётная часть отвечает на живость, готовность, договор и страницу его
просмотра; путь договора без префикса `/api` отвечает отказом.

Последнее — не придирка. Внешний узел отдаёт страницу мини-приложения на любой
неизвестный путь, поэтому клиент, собравший адрес без `/api`, получал бы код
200 и разметку вместо данных. Отказ, выглядящий как успех, ищут дольше всего.

## Что на стенде ещё не сделано

1. **Выложена версия до договора.** `https://triadmind.ru/api/swagger/`
   отвечает `404`; договор и страница появятся после слияния ветки
   `feat/development/r-002-dogovor-api` и пересборки.
2. **Ловушка базового адреса открыта.** Конфигурация из этого документа ещё
   не применена: `https://triadmind.ru/v1/openapi.yaml` возвращает `200`
   и разметку.
3. **Платформа MAX не подключена.** Вебхук чат-бота по адресу `/bot/` объявлен
   конфигурацией, но токен не задан и обновления не принимаются.
4. **Тестовых учётных записей нет** (условия трека, разд. 6.2 п. 3): вход
   не реализован, роли в `DATA-API.yaml` описаны без учётных данных.
