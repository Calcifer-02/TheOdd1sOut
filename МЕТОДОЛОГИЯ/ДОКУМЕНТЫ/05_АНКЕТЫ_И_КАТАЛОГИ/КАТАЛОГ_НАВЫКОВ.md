# Каталог навыков

> Реестр исполняемых инструкций команды и её ИИ-агента. Условие включения каждого навыка ссылается на типизированные факты [профиля системы](ПРОФИЛЬ_СИСТЕМЫ.md), активированные обязательства [модели применимости](ПРАВИЛА_ПРИМЕНИМОСТИ.md) либо стадию. Термины — [глоссарий](../ГЛОССАРИЙ_МЕТОДОЛОГИИ.md).

## Паспорт артефакта

| Параметр | Значение |
|---|---|
| Версия | 1.4 |
| Владелец | Методолог |
| Заполняют | Методолог; команды предлагают кандидатов и сообщают о неприменимых навыках |
| Появляется | до проекта; применимый набор выбирается после профилирования в день 1 |
| Обновляется | при появлении навыка, изменении условия включения и при выводе навыка из обращения |

## Зачем это нужно

Набор навыков растёт быстрее, чем команда успевает его читать, и без условия включения каждый проект получает всё сразу. Каталог отвечает на вопрос, **нужен ли навык этому проекту**, тем же способом, что и [каталог правил](КАТАЛОГ_ПРАВИЛ_ПРОЕКТА.md) — по фактам профиля, а не по названию продукта или отрасли.

Разделение обязанностей внутри пары:

```text
Правило проекта   что считается нарушением и какая проверка его ловит;
                  отвечает сигналом ошибка / предупреждение / решение человека.
Навык             как выполнить работу, которая приводит обязательство
                  в исполненное состояние; сигналов не выдаёт.
```

Навык не подменяет правило и не отменяет его сигнал. Одно обязательство может не иметь навыка, если работа очевидна; два навыка на одно обязательство — признак разрастания набора.

## Форма записи

```text
идентификатор       имя каталога навыка, устойчиво после публикации
назначение          одна фраза: какую работу навык доводит до конца
условие включения   факт профиля, активированное обязательство, стадия
                    либо «общий» — навык предлагается всем проектам
вес контекста       лёгкий / средний / тяжёлый: сколько материала
                    подтягивается при вызове
ближайшая проверка  чем подтверждается, что навык отработал
владелец возможности средство или роль, которые дают нативный результат
зрелость            сделано / частично / не начато / ждёт решения
```

Условием включения не может быть архетип, отрасль, название продукта, краткая `A–E`-сводка или суммарный балл. **Общих навыков должно быть немного**: каждый общий навык платит контекстом во всех проектах сразу.

### Критерий допуска

Навык заводится, если выполнены все три условия:

```text
1. Операция повторяется — в разных проектах или в одном многократно.
   Разовая работа навыком не становится: он будет написан один раз,
   применён один раз и протухнет.
2. У операции есть наблюдаемый результат — артефакт, состояние или замер,
   по которому видно, что работа доведена до конца.
3. Результат можно проверить — названа ближайшая проверка.
```

Не проходит критерий — остаётся руководством, записью в памяти проекта или ничем. **Протухший навык опаснее отсутствующего**: агент следует ему уверенно и воспроизводит устаревший порядок работы.

Обратная сторона критерия — рост каталога управляем: кандидаты берутся из перечня активированных обязательств, у которых навыка пока нет, а не придумываются под каждую задачу.

## Как пользоваться

1. Завершите [профилирование в день 1](ПРОЦЕДУРА_ПРОФИЛИРОВАНИЯ_ДЕНЬ_1.md): условие включения читается из активированных обязательств и фактов.
2. Возьмите общие навыки и те, чьё условие выполнено. Остальные не подключайте: неприменимый навык тратит контекст и провоцирует работу, которой проект не требует.
3. Если обязательство активировано, а навыка для него нет — это нормально: значит, работа выполняется без отдельной инструкции. Заводить навык стоит, когда команда второй раз выясняет одно и то же.
4. Навык, который ни разу не подошёл ни одному проекту, выводится из обращения с причиной, а не остаётся «на всякий случай».
5. Начиная с Gate 2 пакет инженерных практик и его маршрутизатор подключаются из
   библиотеки навыков (подключается в Gate 2).
   Маршрутизатор читает реестр, затем одну карточку и один `SKILL.md`; участнику
   команды не нужно заранее просматривать все инструкции.

## Антипаттерны

```text
- «Навык всем» — условие включения не задано просто потому, что его лень
  выводить; проект платит контекстом за чужую работу.
- «Навык вместо правила» — инструкция выдаёт вердикт о нарушении, подменяя
  сигнал правила и обходя запись архитектурного решения.
- «Два навыка на одно обязательство» — работа расползается по двум
  инструкциям, и ни одна не доводит её до конца.
- «Навык по ярлыку» — условием служит отрасль, архетип или название продукта.
- «Вечный кандидат» — навык объявлен, но не имеет ближайшей проверки, поэтому
  результат его применения нельзя отличить от разговора.
```
