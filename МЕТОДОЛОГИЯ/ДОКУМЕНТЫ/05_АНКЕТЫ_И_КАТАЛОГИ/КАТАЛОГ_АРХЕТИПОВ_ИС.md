# Каталог архетипов информационных систем

> Архетип — справочное начальное заполнение [профиля системы](ПРОФИЛЬ_СИСТЕМЫ.md), а не класс, числовой уровень или доказательство применимости.

## Паспорт артефакта

| Параметр | Значение |
|---|---|
| Версия | 1.0 |
| Владелец | Методолог |
| Заполняют | Методолог по подтверждённым профилям; Архитектор предлагает кандидатов |
| Появляется | до проекта |
| Обновляется | после обкатки различающего профиль случая |

## 1. Назначение

Архетип сокращает вход только там, где повторяются наблюдаемые признаки. Он может предложить:

- начальный набор фактов со статусом `assumed`;
- вопросы, которые обычно различают варианты;
- кандидатов правил;
- типичные информационные дыры;
- примеры необходимых доказательств.

Название продукта никогда не переносится в профиль как доказательство.

## 2. Форма архетипа

```yaml
id: niche_crm
title: Узкоспециализированная система ведения отношений с клиентами
purpose: Стартовое заполнение для реестра клиентов и управляемого рабочего потока
identity:
  all:
    - { fact: data.authoritative_state, op: equals, value: single_store }
    - { fact: domain.workflow_complexity, op: equals, value: medium }
    - any:
        - { fact: interfaces.primary, op: equals, value: web_spa }
        - { fact: interfaces.primary, op: equals, value: web_ssr }
expected:
  { fact: data.transaction_model, op: equals, value: workflow }
incompatible:
  { fact: performance.realtime, op: equals, value: hard }
starterRuleIds:
  - SEC-101
  - API-101
```

| Поле | Назначение |
|---|---|
| `identity` | минимальные признаки, позволяющие предложить архетип |
| `expected` | ожидаемые, но обязательно проверяемые признаки |
| `incompatible` | различающий признак, при котором архетип вводит в заблуждение |
| `starterRuleIds` | кандидаты правил; каждое всё равно проверяет собственное условие |

## 3. Результаты сопоставления

| Результат | Значение |
|---|---|
| `reference_match` | признаки идентичности и ожидаемые признаки подтверждены |
| `compatible_variant` | идентичность подтверждена, но вариант отличается от эталонного |
| `with_extra_obligations` | архетип подходит, однако иные факты активировали дополнительные обязательства |
| `incompatible` | сработал различающий несовместимый признак |

Числового расстояния между архетипом и проектом нет. Отличие интерфейса нельзя приравнять к отличию транзакционных гарантий или правового режима.

## 4. Стартовые архетипы

| Архетип | Признаки идентичности | Что обязательно перепроверить | Что не следует из названия |
|---|---|---|---|
| Публичный информационный сайт | веб-интерфейс; нет собственного пользовательского авторитетного состояния либо оно внешнее | формы, аналитика, персональные данные, доступность | низкая критичность и отсутствие правовых обязательств |
| Справочный диалоговый интерфейс | чат; советующая роль | инструменты, автономность, источники ответа, чувствительные данные | отсутствие состояния и безопасность ответа |
| Узкоспециализированная система ведения отношений с клиентами | единое хранилище; средний рабочий поток; веб-интерфейс | классы данных, роли, внешние стыки, миграция, восстановление | конкретный правовой режим и микросервисная архитектура |
| Документооборот | документы как авторитетные сущности; рабочие состояния | юридическая значимость, подписи, хранение, распознавание, оборудование | наличие саги или обязательной сертификации |
| Сервис обработки событий | сообщения относятся к ядру | семантика доставки, порядок, источник истины, повторное проигрывание | саги, журнал событий как источник истины или высокая нагрузка |
| Автономное мобильное рабочее место | локальная работа без сети | локальная запись, число авторов, разрешение конфликтов, защита устройства | обязательная распределённая синхронизация при режиме только для чтения |
| Вычислительное ядро | алгоритмическая сложность или исследовательская неопределённость | точность, воспроизводимость, ресурсы, предельная задержка | высокая бизнес-логика |
| ИИ-помощник | модель участвует в ответе или рекомендации | автономность, инструменты, данные, оценочный набор, необратимость | чат как единственный интерфейс и право выполнять действия |
| Система, связанная с оборудованием | физическое устройство, датчик или исполнительный механизм влияет на сценарий | доступность стенда, драйверы, безопасное состояние, обслуживание парка | высокая физическая опасность у любого устройства |

## 5. Различающие примеры

```text
Форма, сохраняющая заявки в собственной базе
    → не «без состояния» только потому, что выглядит как лёгкий сайт.

ERP на одной реляционной базе
    → может иметь локальные транзакции; сложность ищется в процессах,
      интеграциях, миграции и обязательствах.

Публичный сайт клиники
    → отрасль «медицина» не делает его управляющей медицинской системой.

ИИ-помощник с REST API, веб-панелью и командной строкой
    → имеет множество интерфейсов; слово «агент» не назначает один из них.

Штрих-код в документообороте
    → сам код не меняет архетип; значение имеют оборудование, драйверы,
      физический процесс и испытательный стенд.
```

## 6. Как добавлять архетип

1. Собрать не менее двух подтверждённых профилей с повторяющейся структурой.
2. Выделить минимальные признаки идентичности, не используя название продукта как условие.
3. Назвать хотя бы один совместимый вариант и один несовместимый контрпример.
4. Отделить ожидаемые факты от подтверждённых.
5. Проверить, что архетип не активирует правило напрямую.
6. Добавить ссылку на обезличенное основание в информационный фонд.
7. Пересмотреть после следующей обкатки.

## Антипаттерны

- **Каталог продуктов** — список названий без различающих признаков.
- **Архетип как сертификат** — совпадение используется как доказательство поддержки.
- **Ближайшая точка** — разнородные отличия складываются в расстояние.
- **Наследование всех практик** — кандидат правила включается без проверки собственного условия.
- **Отраслевой ярлык** — правовой режим и критичность выводятся из сферы деятельности.
