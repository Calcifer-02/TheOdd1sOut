# Входной пакет наследованной системы (шаблон)

## Инструкция по заполнению

> Относится к шаблону, а не к проектному артефакту.

- **Кто заполняет:** архитектор совместно с разработчиком; контекст договорённостей — ведущий.
- **Источники:** устав проекта, профиль режима (ограничение `MODE-LEGACY`); терминология — [ГЛОССАРИЙ_МЕТОДОЛОГИИ.md](../ГЛОССАРИЙ_МЕТОДОЛОГИИ.md).
- **Обязательные поля:** `НСП-id`, тип, состояние, решение о судьбе, риск, связь.
- **Типовые ошибки:** элемент наследия без явного решения; решение «переписываем» без записи в реестре технического долга; элемент высокого риска без записи в реестре рисков.

## Назначение и область действия

Инвентаризация унаследованной кодовой базы, требований, интеграций, данных, договорённостей и ограничений, которые команда получает на старте. Методология поддерживает старт не только «с чистого листа», но и из состояния, где уже есть технический долг, недостоверная документация и частично работающий продукт.

Наследованную базу нельзя принимать как нейтральный старт: она сразу влияет на оценку срока, стоимости, риска, производительности команды и вероятности выхода на МБП.

Артефакт заполняется, если проект стартует не с нуля. Для проектов с чистого листа он не применим (фиксируется как «не применимо: проект с нуля»).

**Связь с режимом разработки.** Если рабочий пакет изменяет существующую кодовую базу, к основному режиму добавляется ограничение `MODE-LEGACY`. Этот пакет — обязательный входной артефакт ограничения; правила выбора и проверки приведены в [матрице режимов](../09_РЕЖИМЫ_РАЗРАБОТКИ/МАТРИЦА_РЕЖИМОВ.md).

## Состав входного пакета

Пакет собирается из семи разделов:

| Раздел | Что включает |
|---|---|
| **Опись наследия** | что досталось команде — перечисление элементов `НСП-id` |
| **Карта кодовой базы** | ключевые модули и зависимости |
| **Известные дефекты** | известные ошибки — переносятся в реестр долга (`ДОЛГ-id`) |
| **Реестр технического долга** | ссылка на [РЕЕСТР_ТЕХНИЧЕСКОГО_ДОЛГА.md](../07_АРТЕФАКТЫ_ПРОДУКТА_И_БИЗНЕСА/РЕЕСТР_ТЕХНИЧЕСКОГО_ДОЛГА.md) |
| **Карта данных и договорённостей** | данные, программные интерфейсы и внешние договорённости, которые нельзя нарушать |
| **Риски наследия** | риски переноса, поддержки и масштабирования — переносятся в [МАТРИЦА_РИСКОВ.md](МАТРИЦА_РИСКОВ.md) |
| **Решение о судьбе** | что сохраняем / переписываем / изолируем / замораживаем — по каждому элементу |

## Соглашения

- Элемент наследия: `НСП-01`, `НСП-02`, … (`НСП` — Наследие).
- Тип элемента: `код`/`данные`/`инфраструктура`/`внешняя договорённость` (включая `API` и `SLA`) / `долг`/`дефект`.
- Решение о судьбе элемента: `сохраняем` (используем как есть) /`изолируем` (ограничиваем доступ, оборачиваем) /`переписываем` (замещаем новой реализацией) /`замораживаем` (не трогаем, но фиксируем) /`удаляем` (выводим из эксплуатации).
- Риск элемента: `низк.`/`сред.`/`выс.` — насколько элемент мешает развитию или несёт угрозу.
- Каждый элемент наследия имеет явное решение о судьбе; элемент без решения — скрытый риск.
