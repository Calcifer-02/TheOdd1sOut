# Первые шаги команды

> Что делает команда в первый день после того, как администратор создал
> репозиторий из шаблона TRIP. Файл удаляется, когда шаблон приведён к проекту.

Порядок шагов не произвольный: каждый следующий опирается на предыдущий.
Хуки `trip-cli` начинают требовать ссылку на идентификатор, поэтому документы,
где эти идентификаторы заводятся, появляются раньше первого содержательного
коммита.

## 0. Где мы находимся

Проект стоит на **Gate 0. Целевой ориентир**.

Контрольный вопрос: понятны ли цель, деловой контекст и передаваемый результат.
Минимальное свидетельство: цель, границы и владелец решения.

Порция методологии этой точки лежит в [МЕТОДОЛОГИЯ/](./МЕТОДОЛОГИЯ/README.md) и
не редактируется. Следующая порция выдаётся ведущим после решения по Gate 0 —
раньше она не нужна и только рассеивает внимание.

## 1. Прочитать

Маршрут — [карта обязательного чтения Gate 0](./МЕТОДОЛОГИЯ/КАРТА_ОБЯЗАТЕЛЬНОГО_ЧТЕНИЯ.md).
Материал считается прочитанным, когда участник может показать связанный
результат: принятое решение, обновлённый артефакт или воспроизводимую проверку.

## 2. Завести рабочую ветку

Прямая запись в `main` закрыта. Имя ветки — по соглашению:

```text
тип/направление[/область]/основание-краткое-имя
```

Имя набирается строчным ASCII: валидатор имени ветки отклоняет кириллицу,
и коммит в ветку с русским именем не пройдёт хук. Для приведения шаблона
к проекту подходит `chore/service/repository-template-to-project`.

## 3. Заменить плейсхолдеры

Плейсхолдер записан как `<пояснение>`. Заменить нужно как минимум:

| Файл | Что заменить |
|---|---|
| [README.md](./README.md) | имя проекта, одно предложение о продукте, команды запуска |
| [AGENTS.md](./AGENTS.md) | имя проекта, структура репозитория, команды, конвенции стека |
| [CLAUDE.md](./CLAUDE.md) | имя проекта |
| [trip.json](./trip.json) | имя проекта |
| [НАДСТРОЙКА_СТЕКА.md](./НАДСТРОЙКА_СТЕКА.md) | чем правило проверяется именно в вашем стеке |
| [CODEOWNERS](./CODEOWNERS) | группы GitLab вашего проекта |
| [.trip/HARNESS_PROFILE.yaml](./.trip/HARNESS_PROFILE.yaml) | идентификатор проекта, инструмент-агент |

Два правила, которые нарушают в первую очередь:

1. **Канон правил — `AGENTS.md`.** `CLAUDE.md` только подгружает его целиком.
   Разошедшиеся файлы дают агенту два расходящихся свода.
2. **Форк канона запрещён.** Всё, что зависит от стека, идёт в
   `НАДСТРОЙКА_СТЕКА.md`, а не в правку правил: канон обновляется методологией,
   и разошедшаяся копия перестаёт получать исправления.

Проверить себя:

```bash
node ИНСТРУМЕНТЫ/скрипты/проверить-скелет.mjs
```

## 4. Поставить средства

```bash
node ИНСТРУМЕНТЫ/скрипты/инструменты.mjs проверить
```

Команда покажет, что уже есть в системе, что доступно к загрузке и чего
не хватает. Получение выпусков (нужен токен на чтение реестра пакетов —
у ведущего):

```bash
node ИНСТРУМЕНТЫ/скрипты/инструменты.mjs установить
```

Выпуски раскладываются в `.trip/tools/<средство>/` — в систему ничего не
ставится. Порядок и настройка доступа — [ИНСТРУМЕНТЫ/README.md](./ИНСТРУМЕНТЫ/README.md).

Обязательный минимум первого дня — `trip-cli`. Бинарь самодостаточен и
запускается прямо из распаковки:

```bash
./.trip/tools/trip-cli/trip init        # Windows: .trip\tools\trip-cli\trip.exe init
./.trip/tools/trip-cli/trip policy
```

Чтобы дальше писать просто `trip`, добавьте каталог `.trip/tools/trip-cli`
в PATH своей оболочки — либо продолжайте вызывать по пути: поведение
одинаковое.

Политика проекта — `trip.json` и валидаторы в `trip/` — уже лежит в
репозитории и отслеживается git: она едет с шаблоном, а не заводится на
каждой машине заново. `trip init` находит её и не трогает, а ставит
управляемые git-хуки. Сразу проверьте, что ограничители живые:

```bash
git commit -m "тест"
```

Коммит должен упасть: нет типа и направления. **Прочитайте текст отказа.**
Проверка, которая не объясняет причину, будет отключена на второй неделе — и
правильно; эта объясняет.

**Гейты идут строгими с первого дня.** `TRIP_GATE_STRICT` в шаблоне равен `"1"`:
необъявленное соглашение зон, ненастроенный линтер кода и прочие пробелы роняют
запрос на слияние, а не желтеют в журнале. Это цена одного пилота, который
четыре захода писал клиент без проверки конструктивных границ и узнал об этом
от Ведущего, а не от конвейера. Если на первой неделе строгость мешает —
выставьте `TRIP_GATE_STRICT=0` на группе и запишите это решением: послабление
должно быть видимым и иметь срок, а не быть умолчанием.

Хук — ранняя остановка на вашей машине, а не гарантия: он снимается одной
командой и не стоит вовсе у того, кто пропустил этот шаг. Правила ветки,
сообщения и журнала подтверждает [гейт следа](./.gitlab/ci/git-trail.yml) в запросе
на слияние — он проходится всеми и всегда. Хук лишь делает правильный путь
дешёвым: узнать об отказе на своей машине дешевле, чем в конвейере.

## 5. Навыки агента: пока ничего не делаем

Навыки подключаются в Gate 2 и приходят с порцией методологии. В шаблоне
лежит только порядок установки — [.agents/skills/](./.agents/skills/README.md).

```bash
node ИНСТРУМЕНТЫ/скрипты/навыки.mjs проверить
```

Сейчас команда ответит, что навыки не установлены, и это не находка. Когда
порция Gate 2 придёт, установка выполняется одной командой и раскладывает
навыки по полю `name`, переносит условия использования и собирает замок
отпечатков.

Рабочие копии шаблонов уже лежат в [docs/ПАКЕТ_АНАЛИТИКИ/](./docs/ПАКЕТ_АНАЛИТИКИ/):

| [ВИДЕНИЕ_И_ГРАНИЦЫ.md](./docs/ПАКЕТ_АНАЛИТИКИ/ВИДЕНИЕ_И_ГРАНИЦЫ.md) | что делаем и, отдельным разделом, чего не делаем |

| [ГЛОССАРИЙ.md](./docs/ПАКЕТ_АНАЛИТИКИ/ГЛОССАРИЙ.md) | термины предметной области проекта |
| [ЖУРНАЛ_КОНТРОЛЬНЫХ_ТОЧЕК.md](./docs/ПАКЕТ_АНАЛИТИКИ/ЖУРНАЛ_КОНТРОЛЬНЫХ_ТОЧЕК.md) | ход и решения контрольных точек |

Наличие шаблона не означает, что его надо заполнять без фактической
потребности. Но цель, границы и владелец решения — это и есть минимальное
свидетельство Gate 0: без них точка не проходится.

## 7. Приёмка первого дня

```text
[ ] рабочая ветка заведена, прямая запись в main не используется
[ ] плейсхолдеры заменены, проверка скелета проходит без находок
[ ] trip init отработал, хуки стоят, тестовый плохой коммит падает с основанием
[ ] trip.json и trip/ на месте и отслеживаются git (git ls-files trip.json trip/)
[ ] main защищён от прямой записи, слияние требует зелёного конвейера
[ ] TRIP_TOOLS_TOKEN задан на группе: гейт следа проверяет, а не сообщает о ненастроенности
[ ] конструктивное соглашение зон объявлено в trip/cast-agreement.json
    (заготовка — trip/cast-agreement.пример.json; политика generic этот файл
     писать разрешает, в отличие от остальной папки trip/)
[ ] гейты идут в строгом режиме: TRIP_GATE_STRICT не выставлен в "0" ни на группе,
    ни в проекте — либо послабление объявлено решением и стоит в журнале точек
[ ] AGENTS.md дополнен структурой, командами и конвенциями продукта
[ ] надстройка стека называет команды сборки, тестов и линтера
[ ] .trip/HARNESS_PROFILE.yaml заполнен минимум до уровня AE0
[ ] проверка навыков проходит; при своём каталоге среды раскладка сделана
[ ] цель, границы и владелец решения записаны в артефактах Gate 0
[ ] запись о первом дне внесена в CHANGELOG.md
[ ] этот файл удалён, блок о шаблоне убран из README.md
[ ] первый содержательный коммит прошёл все проверки
```

Последняя строка — приёмочный критерий. Оснащение, не доведённое до прошедшего
коммита, не проверено.

## Типовые затруднения

| Симптом | Причина | Что делать |
|---|---|---|
| `trip init` не ставит хук | в репозитории уже есть чужой хук | не подменять молча: два владельца одной точки — дефект; сообщить ведущему |
| Коммит с кириллицей ломается | сообщение передано через консольный ключ | коммитить через файл в UTF-8 |
| Агент не видит правила | файл назван не так, как читает конкретный агент | скопировать содержимое `AGENTS.md` под нужным именем |
| Установка средств останавливается | не задан токен на чтение реестра пакетов | получить у ведущего; порядок — в ИНСТРУМЕНТЫ/README.md |
| Нечего указать в коммите | реестра требований ещё нет | завести требование, а не придумать номер |
