# ИМОЛТ: расчёт вывоза и утилизации строительных отходов

| Версия | Дата | Автор |
|---|---:|---|
| 1.1 | 19.09.2026 | Александр Прокошев |

## Что это за проект

Онлайн-сервис для тех, кто вывозит отходы строительства и сноса в Москве
и Московской области: заказчиков работ, перевозчиков и демонтажных компаний.

Сервис считает стоимость вывоза по типам отходов и объёму, раздельно учитывая
перевозку и утилизацию, подбирает полигоны с действующими ценами и статусом
приёма, показывает маршрут и готовит коммерческое предложение. Ценность сервиса
держится на актуальности справочников: цены и статусы полигонов меняются часто,
а ошибка в них превращается в неверную смету.

> **Состояние репозитория: плацдарм.** Службы поднимаются, видят друг друга
> и отвечают на запросы работоспособности. Предметной логики расчёта, сценариев
> чат-бота и экранов мини-приложения в них ещё нет: разделы ниже отмечают, что
> уже работает, а что предстоит.

## Основной пользовательский сценарий

Пользователь вводит адрес вывоза, выбирает типы отходов и объём, получает расчёт
с раздельным учётом перевозки и утилизации, сравнивает полигоны по итоговой
стоимости и выгружает коммерческое предложение.

**Сценарий пока не реализован в коде.** Сегодня проверяется только связность
служб, см. раздел «Пошаговый сценарий проверки».

## Состав и архитектура

| Служба | Назначение | Технологии | Порт внутри | Порт снаружи |
|---|---|---|---:|---|
| `db` | Хранилище справочников, расчётов и заявок | PostgreSQL 17 | 5432 | `POSTGRES_PORT` |
| `api` | Расчётная часть: справочники, расчёт, коммерческое предложение | .NET 10, ASP.NET Core, Npgsql | 8080 | `API_PORT` |
| `bot` | Чат-бот MAX: приём обновлений платформы | .NET 10, ASP.NET Core | 8080 | `BOT_PORT` |
| `miniapp` | Мини-приложение MAX: интерфейс расчёта | React 19, Vite 7, nginx | 80 | `MINIAPP_PORT` |

Связи между службами: `miniapp → api` через проксирование пути `/api` внутри
nginx, `api → db` по строке подключения, `bot → api` по внутреннему адресу.
Наружу открыты все четыре порта, чтобы каждую службу можно было проверить
отдельно.

## Как запустить локально

```sh
cp .env.example .env          # один раз: подставьте пароль базы и токен чат-бота
docker compose up --build     # одна команда поднимает все локальные компоненты
```

Нужны только Docker и Docker Compose. Устанавливать .NET SDK и Node.js
не требуется: сборка идёт внутри образов и занимает около 16 секунд при уже
загруженных базовых образах.

## Порядок остановки и повторного запуска

```sh
docker compose stop            # остановить, данные сохранить
docker compose start           # поднять снова
docker compose down            # снести контейнеры и сеть, тома оставить
docker compose down --volumes  # снести вместе с данными базы
```

После `down` повторный запуск выполняется той же командой `docker compose up --build`.

## Переменные окружения

Образец со значениями по умолчанию лежит в `.env.example`. Рабочих токенов,
паролей и ключей в репозитории нет: файл `.env` в отслеживание не попадает.

| Переменная | Назначение | Значение в образце |
|---|---|---|
| `API_PORT` | Порт расчётной части на машине | `18080` |
| `BOT_PORT` | Порт чат-бота | `18081` |
| `MINIAPP_PORT` | Порт мини-приложения | `15173` |
| `POSTGRES_PORT` | Порт базы данных | `15432` |
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` | Учётные данные базы | `imolt`, `imolt`, заглушка |
| `MAX_BOT_TOKEN` | Токен чат-бота MAX, выдают организаторы | пусто |
| `MAX_API_BASE_URL` | Адрес интерфейса чат-ботов MAX | пусто |
| `MINIAPP_PUBLIC_URL` | Публичный адрес мини-приложения по HTTPS | пусто |

Порты по умолчанию смещены от привычных 8080, 5173 и 5432: на машине
разработчика они обычно заняты, и запуск падает с `port is already allocated`.

## Зависимости

| Компонент | Чем зафиксированы версии |
|---|---|
| `api`, `bot` | `packages.lock.json` рядом с каждым проектом; в образе восстановление идёт в режиме замка и падает при расхождении |
| `miniapp` | `package-lock.json`; в образе выполняется `npm ci` |
| Базовые образы | Теги закреплены в `Dockerfile`: `sdk:10.0`, `aspnet:10.0`, `node:24-alpine`, `nginx:1.29-alpine`, `postgres:17-alpine` |

## Внешние сервисы и интеграции

| Сервис | Для чего нужен | Состояние |
|---|---|---|
| Платформа MAX | Среда решения: чат-бот и мини-приложение | не подключена. Мини-приложение требует адреса по HTTPS, вебхук чат-бота требует внешнего адреса; внутри Docker это не воспроизводится |
| Подсказки адресов | Ввод адреса вывоза | не подключены, поставщик не выбран |
| Расчёт расстояний и внешние карты | Маршрут до полигона | не подключены, поставщик не выбран |

## Работа с данными

База данных поднимается пустой: схема и миграции не заведены, способ их ведения
выбирается вместе с первой предметной областью. Справочники групп отходов,
полигонов и тарифов пока существуют только как демонстрационные значения
в макетах.

**Тестовых данных в репозитории нет.** Когда они появятся, их происхождение
указывается явно: подготовленные и модельные данные должны отличаться от данных
официального источника.

## Пошаговый сценарий проверки

```sh
sh tests/devops/проверка-запуска.sh
```

Скрипт разбирает `compose.yaml`, сверяет состав служб, поднимает решение одной
командой, проверяет ответы и убирает за собой. Ожидаемый вывод:

```text
расчётная часть: живость /health                ок (200)
расчётная часть: готовность /ready (видит базу) ок (200)
чат-бот: живость /health                        ок (200)
мини-приложение: страница                       ок (200)
мини-приложение → расчётная часть через /api    ок (200)
чат-бот принимает вебхук                        ок (200)
Плацдарм развёртывания проверен: отказов нет.
```

То же вручную, с примерами ожидаемого поведения:

| Запрос | Ожидаемый ответ |
|---|---|
| `curl http://localhost:18080/health` | `{"service":"api","status":"ok"}` |
| `curl http://localhost:18080/ready` | `{"service":"api","status":"ready","database":"reachable"}` |
| `curl http://localhost:18081/health` | `{"service":"bot","status":"ok","token_configured":false}` |
| `curl http://localhost:15173/api/health` | ответ расчётной части, полученный через мини-приложение |
| Открыть `http://localhost:15173/` | страница мини-приложения со строкой «Расчётная часть отвечает» |

Если расчётная часть отвечает `not_ready`, в теле ответа названа причина: не задана
строка подключения или база недоступна.

## Известные ограничения

1. Предметной логики нет: расчёт, подбор полигонов, коммерческое предложение,
   сценарии чат-бота и экраны мини-приложения не реализованы.
2. Схемы базы данных и миграций нет.
3. Решение не подключено к платформе MAX.
4. Внешние интеграции (подсказки адресов, расстояния, карты) не выбраны.
5. Способ запуска проверен на машине разработчика, проверка «с чистой машины»
   не выполнялась.

```text
devops/       запуск и эксплуатация

ux/           макеты экранов и правила интерфейса
client/       материалы заказчика и условия направления

```
