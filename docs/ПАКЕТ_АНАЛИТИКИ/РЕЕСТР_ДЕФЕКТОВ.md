## Инструкция по заполнению

> Относится к шаблону и не входит в проектный артефакт.

- **Назначение:** оставить в репозитории безопасную, долговечную и проверяемую
  историю каждого `BUG-id`. Реестр не заменяет оперативное хранилище диагностических материалов.

- **Граница данных:** исходные описание и маршрут, снимки экрана, диагностические
  строки, навигационный след, персональные данные и секреты в автоматическую
  проекцию не переносятся. Они хранятся отдельно с ограниченным доступом.

- **Основные связи:** после триажа у дефекта подтверждается затронутое
  требование `R-id` и ближайшая нарушенная проверка: критерий `AC-id` и/или
  воспроизводящий либо регрессионный `TC-id`. `UC-id`, `ADR`, `AR-id` и другие
  узлы добавляются только при фактическом влиянии; стадия и класс важности
  выводятся из требования, а не копируются в реестр. Если подходящего `AC-id`
  или `TC-id` ещё нет, создаётся ближайшая проверка либо явно фиксируется
  тестовый долг; случайная связь ради заполнения недопустима.

- **Анализ влияния:** рассматривается релевантный подграф, а не формальный список
  технических слоёв. Для каждой трасс-цели фиксируются тип узла, решение
  `требует изменения`/`не требует изменения`, основание и автор. Для
  изменяемой цели обязательно стратегическое направление.

- **Трасс-цели:** требование, критерий приёмки, сценарий, архитектурное решение,
  риск, гипотеза, кодовый якорь, тест-кейс, раздел документа, метрика,
  подтверждение, практика или обоснованное расширение графа проекта.

- **Направления:** Аналитика / Разработка / QA и тесты / UX и эстетика / Клиент.
  Направление определяется смыслом изменения, а не папкой.

- **Итерации:** одна итерация относится к одному направлению. Если дефект затрагивает
  несколько направлений, они закрываются последовательными итерациями.

- **Закрытие:** нельзя считать дефект исправленным или проверенным, пока каждая
  подтверждённая пара «трасс-цель × направление» не имеет фактического изменения,
  а все обязательные проверки всех итераций — успешного результата и свидетельства.

- **Автоматическая проекция:** инструмент может обновлять только ограниченный
  служебными маркерами раздел. Ручные пояснения вне маркеров сохраняются.
  Изменение самого реестра не считается исправлением документации. Агент может
  добавить только состояние `кандидат` по известным трасс-целям и проверяемому
  неуспешному evidence; он не подтверждает, не отклоняет и не закрывает дефект.
  Методологический шаблон не является реестром проекта и автоматической записи
  не принимает.

### Что автоматизируется, а что подтверждает человек

| Сигнал или решение | Допустимая автоматизация | Обязательное подтверждение |
|---|---|---|
| Страница, снимок, время, навигационный след | Захватить при регистрации с разрешения пользователя | Проверить достаточность контекста |
| `R-id`/`AC-id`/`TC-id` | Предложить по странице, явному идентификатору и ближайшей проверке | Подтвердить требование и нарушенную проверку; `UC-id` добавить только для применимого потока |
| Кандидат трасс-цели | Предложить по трасс-ссылкам, маршруту и известному графу | Решить, есть ли смысловое влияние |
| Изменённый файл | Получить из Git и сопоставить с настроенной целью | Подтвердить, что изменение относится к исправлению |
| Стратегическое направление | Сопоставить объявленное направление в области заголовка с содержанием изменения | Выбрать по смыслу изменения; расхождение разобрать |
| Связь с ADR, риском, гипотезой, метрикой, практикой или подтверждением | Показать существующее ребро либо предложить кандидата | Не создавать новое смысловое ребро без решения человека |
| Результат проверки | Принять статус, команду и свидетельство | Убедиться, что проверка способна опровергнуть исправление |
| Баг-кандидат от агента | Дедуплицировать evidence и добавить строку `кандидат` только внутри управляемой секции | Выполнить триаж, подтвердить связи, важность и состояние |

## Назначение и область действия

Реестр хранит минимальную безопасную трасс-проекцию всех дефектов проекта.
Полный контекст воспроизведения, анализ влияния, итерации, изменения и
свидетельства остаются в связанных операционных записях и графе; здесь
сохраняются `BUG-id`, состояние, основная связь с `R-id`, ближайшие `AC-id` /
`TC-id`, задача исправления и дата обновления.
