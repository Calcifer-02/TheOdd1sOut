## Назначение и область действия

Приёмочные тесты — формализованные критерии приёмки требования в виде исполняемых (или квази-исполняемых) сценариев. Каждый тест проверяет конкретное требование и даёт бинарный ответ «выполняется / не выполняется» — это метрика приёмки функциональности.

## Соглашения

- Формат: Gherkin (`Given`/`When`/`Then`) или его русская версия (Дано / Когда / Тогда).
- Идентификатор сценария (`AC-id`): `AC-<номер проверяемого требования R-id><буква>`, напр. для `R-007` — `AC-007a`, `AC-007b`. Единая точка склейки с матрицей трассируемости и тестовыми сценариями.
- Привязка обязательна: каждый сценарий связан с требованием (`R-id`), пользовательской историей (`US-id`) и сценарием использования (`UC-id`).
- Класс важности (`К1`/`К2`/`К3`) указывается в шапке `Feature`.
- Шаг `Then` формулируется проверяемо: наблюдаемый факт или состояние, а не описание реализации.

## Структура приёмочного теста

```gherkin
Feature: <название функциональности, ссылка на R-id из реестра>
  Контекст: <короткое описание для команды>

  # Связи
  # R-id: R-001, R-002
  # US-id: US-007
  # UC-id: UC-002
  # Класс важности: К1

  # Scenario-id: AC-001a
  Scenario: <название сценария>
    Given <предусловие>
    And   <дополнительное предусловие>
    When  <действие пользователя или системы>
    And   <дополнительное действие>
    Then  <ожидаемый результат>
    And   <дополнительный ожидаемый результат>
```

Заполняется по срезам реализации: критерий заводится раньше кода, который его
закрывает. Здесь — служебные точки, область «справочники» и область «расчёт»;
сделка, доступ и ведение справочников получают свои критерии вместе со своими
срезами.

Три соглашения этого раздела:

- **Пользовательские истории (`US-id`) не заведены** — документ
  [ПОЛЬЗОВАТЕЛЬСКИЕ_ИСТОРИИ.md](ПОЛЬЗОВАТЕЛЬСКИЕ_ИСТОРИИ.md) остаётся шаблоном.
  Поле не заполняется выдуманным значением: разрыв виден, а не замаскирован.
- **Проверки автоматические.** Ручные карточки тест-кейсов
  ([ТЕСТОВЫЕ_СЦЕНАРИИ.md](ТЕСТОВЫЕ_СЦЕНАРИИ.md)) не заводятся, пока нет ручного
  прогона: критерий связывается с кодом проверки якорем `@ac` по стандарту
  трассируемости, и это и есть воспроизводимое подтверждение.
- **Данные сквозные.** Везде, где нужен пример, берётся канонический набор
  договора: адрес «г Москва, ул Годовикова, д 9», группы `beton-lom` и
  `drevesina`, полигоны `vostok-timohovo` и `iksha`, дата актуальности

### Служебные точки

```gherkin
Feature: Живость и готовность расчётной части (R-011)
  Контекст: внешний узел и оркестратор решают по этим точкам, отдавать ли
  службе трафик. Живость не должна зависеть от базы данных, иначе перезапуск
  базы выглядит как отказ службы.

  # Связи
  # R-id: R-011
  # US-id: не заведены
  # UC-id: UC-001
  # Класс важности: К1

  # Scenario-id: AC-011a
  Scenario: живость не зависит от базы данных
    Given расчётная часть запущена
    And   база данных остановлена
    When  выполняется GET /health
    Then  ответ имеет код 200
    And   тело содержит status «ok»

  # Scenario-id: AC-011b
  Scenario: готовность отличает доступную базу от недоступной
    Given расчётная часть запущена и видит базу данных
    When  выполняется GET /ready
    Then  ответ имеет код 200
    And   тело содержит status «ready» и database «reachable»

  # Scenario-id: AC-011c
  Scenario: готовность отказывает при недоступной базе
    Given расчётная часть запущена
    And   строка подключения к базе данных не задана
    When  выполняется GET /ready
    Then  ответ имеет код 503
    And   тело содержит status «not_ready» и причину отказа
```

### Стоимость по формуле

```gherkin
Feature: Стоимость считается по формуле перевозки и утилизации (R-017, R-018, R-019)
  Контекст: перевозка = тонны × цена группы за тонна-километр × расстояние по
  дорожной сети; утилизация = тонны × тариф полигона по группе; итог — сумма.
  Числа сверяются с каноническим примером договора, а не с реализацией.

  # Связи
  # R-id: R-017, R-018, R-019, R-020
  # US-id: не заведены
  # UC-id: UC-001
  # Класс важности: К1

  # Scenario-id: AC-018a
  Scenario: перевозка считается из цены группы и плеча перевозки
    Given адрес вывоза «г Москва, ул Годовикова, д 9»
    And   цена перевозки группы «beton-lom» — 12,00 рубля за тонна-километр
    And   плечо до полигона «vostok-timohovo» — 45 километров
    When  выполняется POST /v1/calculations с 20 тоннами этой группы
    Then  ответ имеет код 201
    And   стоимость перевозки до «vostok-timohovo» равна «10800.00»

  # Scenario-id: AC-018b
  Scenario: утилизация считается из тарифа полигона по группе
    Given тариф «vostok-timohovo» по группе «beton-lom» — 450,00 рубля за тонну
    When  выполняется POST /v1/calculations с 20 тоннами этой группы
    Then  стоимость утилизации до «vostok-timohovo» равна «9000.00»

  # Scenario-id: AC-018c
  Scenario: совокупная цена равна сумме перевозки и утилизации
    When  выполняется POST /v1/calculations с 20 тоннами группы «beton-lom»
    Then  совокупная цена до «vostok-timohovo» равна «19800.00»
    And   совокупная цена до «iksha» равна «20080.00»

  # Scenario-id: AC-019a
```
