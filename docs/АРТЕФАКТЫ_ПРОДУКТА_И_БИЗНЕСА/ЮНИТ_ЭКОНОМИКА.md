# Юнит-экономика (шаблон)

## Инструкция по заполнению

> Относится к шаблону, а не к проектному артефакту.

- **Кто заполняет:** ведущий совместно с аналитиком; допущения подтверждает заказчик.
- **Источники:** метрики использования, оценки трудозатрат команды, тарифы поставщиков и облачных служб, фактические эксплуатационные измерения; терминология — [ГЛОССАРИЙ_МЕТОДОЛОГИИ.md](../../МЕТОДОЛОГИЯ/ДОКУМЕНТЫ/ГЛОССАРИЙ_МЕТОДОЛОГИИ.md).
- **Обязательные поля:** единица, доход на юнит, прямые затраты на юнит, маржа на юнит, точка окупаемости, допущения (`Д-id`).
- **Типовые ошибки:** строка без пометки «факт» или «допущение»; допущение без способа проверки; единица не зафиксирована явно; учтена только цена разработки без вычислительных и человеческих затрат.

## Назначение и область действия

Юнит-экономика — расчёт экономики на один юнит (клиент / пользователь / транзакция / операция — что выбрано единицей): что юнит приносит и сколько стоит. Показывает, сходится ли экономика «в малом», прежде чем говорить о масштабе. Единая точка, откуда экономическая модель забирает маржу на юнит и точку окупаемости.

## Соглашения

- Единица (`юнит`) выбирается одна и фиксируется явно (клиент / транзакция / иное).
- Каждая строка расчёта помечается как `факт` (есть данные) или `допущение` (оценка); допущения нумеруются `Д-01`, `Д-02`, … и проверяются.
- Деньги и единицы измерения указываются явно; период (на месяц / на транзакцию) фиксируется.
- Прямые затраты считаются по двойной оценке — вычислительные и человеческие, не только цена разработки.

## Поля модели

| Поле | Что вносить |
|---|---|
| Единица | что считается юнитом |
| Доход на юнит | выручка / экономия / иной измеримый эффект |
| Прямые затраты на юнит | вычислительные и человеческие |
| Маржа на юнит | доход - затраты |
| Точка окупаемости | при каком объёме юнитов проект выходит в плюс |
| Допущения | список `Д-id` с источником и способом проверки |
| Чувствительность | как меняется маржа при отклонении ключевых допущений (+/-) |
