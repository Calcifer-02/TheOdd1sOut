# trip/

Файлы настроек trip **под контролем версий** — едут вместе с репозиторием.

Здесь лежат js-скрипты проверок сообщения, ветки и changelog, на которые
ссылаются политики в `trip.json` (пути задаются относительно этой папки).

## Что здесь чьё

Папка держит файлы двух владельцев, и политика `generic` различает их.

**Методология — закрыта на запись.** `trip.json`, валидаторы `msg.js`,
`branch.js`, `changelog.js`, происхождение цепочки средств `toolchain.json`,
образцы. Правятся только под политикой `policies-only` и отдельным коммитом:
правка методологии не смешивается с правкой содержания проекта.

**Настройки средств проекта — открыты на запись под `generic`:**

```text
trip/cast-agreement.json    конструктивное соглашение зон (КАСТА)
trip/trace-policy.json      политика сканирования кодовых якорей (трасса)
```

Это не послабление, а исправление: средства ищут свою настройку именно здесь,
по умолчанию и без ключей. Пока папка была закрыта целиком, проект выносил
настройку в другое место, средство её не находило, а `hook install` печатал
вызов без пути — и проверка держалась на том, что кто-то помнит про ключ.
В одном пилоте это кончилось четырьмя заходами без проверки границ, а политика
трассы раздвоилась на две расходящиеся копии.

Перечень исключений задан в `trip.json` выражением, а не подстановкой: новый
файл в `trip/` закрыт по умолчанию, и открыть его — отдельное решение.

Локальный state инструмента (активная политика) — отдельно, в `.trip/` (в .gitignore).
